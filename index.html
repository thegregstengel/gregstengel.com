the arc

  1. 01

    Phones, then racks

    Started in DSL tech support, talking strangers through modem lights. Then small-business IT, then sysadmin for 100+ web servers: Apache, WebSphere, and Tomcat on Red Hat, IIS on Windows, nearly all of it on VMware. The habit that stuck: figure out what broke, then write it down.

  2. 02

    Making the noise useful

    Somebody had to make sense of the logs, so I taught myself Splunk and built the platform. Then ran Splunk and Enterprise Security for a large enterprise: upgrades, performance, and dashboards people actually used. Collecting everything is easy; making it useful is the job.

    • Multi-datacenter Splunk platform

      Built Splunk across three datacenters and 2,500+ nodes. Puppet handled forwarder rollout; scripts handled new index configuration. Less hand configuration, fewer opportunities to get creative by accident.

  3. 03

    AWS becomes home turf

    After a short stop deploying OpenStack with Ansible, AWS, and it stuck. Architect for managed cloud customers: their environments built in Terraform, compliance enforced with Cloud Custodian, the fleet run with Puppet, and Splunk watching all of it. Most of what I have built since runs here.

    • Monitoring that earns its keep

      Built a clustered Splunk platform in AWS to monitor customer environments. Custom integrations, 50+ dashboards per customer app, and summary indexing turned scattered resource data into useful answers.

    • AWS security monitoring pipeline

      Built a CloudFormation stack to send AWS security logs and events through Kinesis Firehose into Splunk HEC, with SNS notifications. Covered root logins, unauthorized API calls, and IAM and network changes. Fewer places to look when something looked wrong.

  4. 04

    Leading it

    Managed the cloud engineering team, then directed it, and later ran observability as a senior director. Cut alert noise so support saw the real problems, moved customers off third-party backup tools onto native AWS Backup, and got engineers sharing what they built instead of reinventing it. Kept my hands in the tooling even when the calendar filled with meetings.

    • Managed observability offering

      Built Elastic Cloud observability for operations, then turned it into something customers could buy: data-source onboarding, dashboards and alerts, chargeback, and customer-specific runbooks.

  5. 05

    Automate the repeat work

    Chose the keyboard again and pointed it at AWS. Python, Bash, Lambda, EventBridge, CloudFormation, Terraform, SSM: patching, backups, migrations, even disk alarms that create and remove themselves. Kubernetes on EKS and some Splunk consulting along the way, plus Azure and GCP when a customer needed them. If a job shows up twice, it gets a script.

    • Backup & compliance automation

      Automated AWS backups, patching, and compliance checks with CloudFormation, AWS Config, SSM, and tagging standards, rolled out across accounts with Python tooling so every deployment looked the same.

    • Hybrid file-sync pipeline

      Connected SFTP and SMB workflows across AWS and on-prem using Lambda, S3, and DynamoDB. Automated file mapping and sync so moving files didn’t need to be somebody’s job.

    • Fewer IPs, smaller bills

      Built automation to migrate and consolidate public IPs, reducing per-application IP costs. Small pieces of infrastructure add up when the meter never stops.

  6. 06

    Platform & identity

    Mostly platform work in AWS these days: EKS across three regions, rolling Envoy and Linkerd out across the environments and clusters, ArgoCD for deploys, Vault for secrets. Alongside it, a big identity project: Okta-backed Identity Center, carried through EKS access entries into Kubernetes RBAC. All of it in Terraform/Terragrunt through GitLab CI. Make the right access easy and the wrong access difficult.

    • Identity modernization

      Replaced legacy IAM access with Okta-backed Identity Center across a multi-account AWS environment. Reusable Terraform/Terragrunt modules and GitLab CI made permission changes repeatable. Least privilege, maintained in code.

    • Multi-region EKS access

      Operated EKS across three AWS regions, mapping Identity Center access into Kubernetes RBAC with EKS access entries, with ArgoCD deployments on top. Managed Vault secrets and ingress alongside it, with runbooks so the access path didn’t live in one person’s head.

  7. 07

    Agents in the loop

    Claude Code, Cursor, and Codex are part of the daily workflow now. I scope the work, run coding agents against it, and review what comes back: infrastructure code, automation, runbooks. Delivery that took a month takes days. The agents do a lot of the typing. I still own what ships.
