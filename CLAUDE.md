# gregstengel.com

## What this is

Personal site for Greg Stengel. Two distinct parts:

1. **Landing page** -- custom HTML/CSS/JS at site root (`/`), the "sheet" design
2. **Blog** -- Jekyll with Chirpy theme at `/blog/`

Hosted on GitHub Pages. Deployed via GitHub Actions to the `gh-pages` branch.

## Tech stack

- Jekyll (static site generator for the blog)
- Chirpy theme (dark mode, TOC, syntax highlighting, search, categories, tags)
- GitHub Pages (hosting)
- GitHub Actions (CI/CD, auto-deploys on push to `main`)
- Custom HTML/CSS/JS (landing page, not managed by Jekyll; vanilla, no build step)

## Landing page (the "sheet")

- `index.html`, `styles.css`, `palette.js`, `background.js`, `console.js`, and
  `music.js` at the repo root
- Standalone HTML/CSS/JS, not processed by Jekyll; vanilla, no build step
- Creative direction is captured in `BRIEF.md` at the repo root (see its **v3**
  section, which supersedes the earlier bento/maximalist direction) -- read it
  before touching copy or design
- The page is **professional content first**: experience, builds, toolkit,
  certifications, peer recommendations. The homelab tiles are gone (that material
  is blog-post territory). The fun is small and hidden: the π, the console, the
  name tooltip, the soundtrack.
- **Anti-resume rule:** the professional content is anonymized on purpose -- **no
  employer names, no dates, no tenure/durations**. Experience is chunked into
  generalized *eras*; builds are described by what was built, not where. Keep it
  that way. This includes certifications: no issue or expiry dates.
- **No lies rule:** eras may be massaged and need not map 1:1 to the real
  timeline, but every claim must be true. The source of truth is Greg's LinkedIn
  experience section plus what he has said directly.
- Any changes here are purely frontend work

### Design

- **One sheet, one column.** A single terminal-window document (`.sheet`, with a
  title bar) over the icon wall, max-width 920px. Sections (`.sec`) are separated
  by hairlines and headed `// label ————`. No tile grid.
- **Dark by construction**, one phosphor accent (`--acc`) over a near-black base,
  alarm-red (`--hot`) reserved for sparing use. No light mode and no
  `prefers-color-scheme` branch.
- **Two palettes, alternating.** Amber (`#ffb454`, the `:root` default) and green
  (`#6cff5a`, `:root[data-palette="green"]`), both defined at the top of
  `styles.css`. `palette.js` flips between them on every page load. Never
  hard-code an accent colour; use `var(--acc)` / `color-mix()` so both work.
- **Type:** Space Grotesk (display) + JetBrains Mono (body, labels, terminal
  voice), from Google Fonts.
- **Background:** the animated "stack wall" -- drifting, fading tech-icon SVGs
  generated by `background.js` from `assets/icons/`, hover-to-name. Greg likes
  this as it is; don't restyle it.

### Structure (in DOM/scroll order)

- **Hero:** terminal kicker (`greg@stengel:~$ whoami`), name as `h1` (carries the
  `data-tooltip="Shall we play a game?"` easter egg), role/location line, the
  headline, a subhead that leads with AWS / automation / coding agents, and the
  social link row (GitHub, LinkedIn, Instagram, X).
- **The arc:** seven anonymized eras as a timeline (`01 Phones, then racks` →
  `07 Agents in the loop`). The signature builds are **nested inside the era they
  belong to** (`.build-list`), not a separate section. Emphasis is on public
  cloud (AWS), automation, and AI-assisted delivery (Claude Code / Cursor /
  Codex); OpenStack is deliberately a passing mention.
- **The toolkit:** label/items rows (`dl.kit`): Cloud, AI & Agents,
  Observability, Infrastructure as Code, Platform & Delivery, Security &
  Identity, Automation, Foundations.
- **Certifications:** full names on each chip, grouped *Current* (Splunk) and
  *Previously held* (AWS, FinOps). No dates.
- **On the record:** anonymized recommendation pull-quotes with stripped
  relationship tags (`— former manager`, etc.). No names/companies/dates.
- **Off the clock:** personal projects as linked cards (Big Bang Smugglers,
  Clickarr, Protovision Games). Real project names are fine here; the
  anti-resume rule covers employers, not side projects.
- **Foot:** location line, the `sound` toggle hint, and **the π**.

**The blog is intentionally unlisted.** There is no blog tile or CTA on the
landing page; the only way in is the `blog/` link typed out inside the console
(and the 404 page, which still links to it). Don't add a visible blog link.

### Behavior (JS)

- **`palette.js`:** loaded synchronously in `<head>` *before* the stylesheet so
  there is no flash. Reads the last palette from `localStorage`, sets the other
  one on `<html data-palette>`, and updates `theme-color`. First visit or blocked
  storage gets a coin flip. `404.html` loads it too.
- **`background.js`:** builds the icon wall on a jittered grid, hover-to-name
  labels (`data-label`), pauses animation while the tab is hidden, caps icon
  count lower on mobile, and ignores height-only resizes. Respects
  `prefers-reduced-motion`. `.panel` is `pointer-events: none` (its children
  re-enable it) so the wall stays hoverable in the page margins.
- **`console.js`:** the hidden `/whoami` console (`role="dialog"` modal). Opens
  from **the π** in the page foot (a nod to *The Net*) or the unadvertised `?`
  key; closes on `Esc`/click-outside. Types out a short session (the `SESSION`
  array; a step with `href` renders as a link, which is how the blog link gets
  in), traps Tab inside the dialog, respects `prefers-reduced-motion`, and
  restores focus on close. The opener is found by `[aria-controls="console"]`.
- **`music.js`:** the sound control (fixed bottom-left pill, `#music`), modelled
  on omarchy.org's. The soundtrack is conceptually *always playing* from page
  load on a virtual clock; un-muting joins it in progress, muting ramps a
  GainNode to zero so the position stays live. Four EQ bars run off a live
  `AnalyserNode` when sounding and off a **precomputed spectrum**
  (`assets/music/<slug>.json`) while muted, so they move before any audio is
  fetched. Progress bar + invisible range input for seeking; hovering the seek
  strip swaps artist for `m:ss / m:ss`. Toggle via the art button, the `m` key,
  or the `sound` foot hint. Never autoplays; only the ~37 KB JSON loads up
  front. Hidden under 640px (the foot hint still works). Track metadata lives
  in `TRACK` at the top of the file.
  - **Track:** *Newer Wave* by Kevin MacLeod, **CC BY 4.0** from incompetech.com.
    Attribution is required and lives in three places: the artist link in the
    pill (`index.html`, with the full credit in its `title`), the HTML comment
    above the control, and the Credits section of `README.md`. Keep all three
    if the track changes. Required wording: `"Newer Wave" Kevin MacLeod
    (incompetech.com) Licensed under Creative Commons: By Attribution 4.0
    https://creativecommons.org/licenses/by/4.0/`.
  - **Assets:** `assets/music/<slug>.{mp3,png,json}`. To swap tracks: drop
    `<slug>.mp3` + square `<slug>.png` art into `assets/music/`, run
    `python3 scripts/gen-music.py --analyze <slug>` for the spectrum JSON, and
    update `TRACK` in `music.js` plus the title/artist/art in `index.html`.
    Running the script with no args regenerates the synth placeholder loop
    (*Phosphor Idle*) for testing without a licensed track.

### Site-wide plumbing (404, favicons, robots, sitemap)

- **`404.html`** is a standalone page reusing `styles.css` (the `.sheet` /
  `.sec--hero` classes), `palette.js` + the icon wall. GitHub
  Pages serves the *root* `404.html` for every missing URL on the domain (the
  blog's `blog/404.html` is never used), so it must use **absolute** asset paths
  (`/styles.css`, `/palette.js`, `/background.js`); `background.js` loads icons from
  `/assets/icons/` for the same reason. It echoes the missing path via
  `textContent` and shows an extra hint for `/blog/...` URLs. `noindex`.
- **Favicons** are a `>_` prompt mark in the site palette, authored as a tiny
  hand-written SVG (`assets/favicons/favicon.svg`) and rasterized from it. The
  same set is duplicated into `blog/assets/img/favicons/` under the filenames
  Chirpy's `_includes/favicons.html` expects, so no theme source is edited. If
  the mark changes, edit that SVG and run `scripts/gen-favicons.js` (needs
  `sharp` + `to-ico`; usage at the top of the file) to regenerate **both** sets.
- **robots.txt / sitemap:** `robots.txt` points at `/sitemap.xml`, a sitemap
  *index* listing `/sitemap-pages.xml` (root, hand-maintained) and
  `/blog/sitemap.xml` (generated by `jekyll-sitemap` on every blog deploy). Add
  new root pages to `sitemap-pages.xml`; blog pages need nothing.
- **Share image:** `assets/og-card.png` (1200x630) is the landing page's
  `og:image`; a copy at `blog/assets/img/og-card.png` is the blog's
  `social_preview_image`, used by any post without its own `image:`. Keep the
  two in step if the headline changes.
- **Meta:** the landing page carries title/description/canonical/OG/Twitter +
  a `Person` JSON-LD block. Blog pages get theirs from `jekyll-seo-tag`, driven
  by `description:` in post/tab front matter -- keep that field filled in.
- `deploy-site.yml` triggers on these root files and **excludes** `CLAUDE.md`,
  `BRIEF.md`, `README.md`, `.claude/` and `scripts/` from the published site.

### Editing notes

- Voice is first-person, pointed, peer-level (per `BRIEF.md`), and professional
  substance leads. Headline: "Two decades making clouds behave."
- **Never add employer names, dates, or durations** -- that's the whole point of
  the eras/anonymized-builds treatment.
- New experience goes into the arc: extend the relevant era's text, and add a
  build card only for something concrete that was actually built.
- The icon wall reads slugs from `background.js`'s `ICONS`/`LABELS`; every slug
  must have a matching SVG in `assets/icons/`.
- Recommendation quotes are trimmed/anonymized from real LinkedIn recs; keep tags
  generic (relationship only).
- The favicon and the blog retint are green. That still matches one of the two
  palettes, so they were left alone.

### Known quirks

- Blog lives in `/blog/` subdirectory with `baseurl: "/blog"`
- Jekyll pagination (`jekyll-paginate`) does not work correctly in subdirectory setups
- The home layout (`_layouts/home.html`) was patched to loop through `site.posts` directly instead of relying on `paginator.posts`
- Posts with `pin: true` display at the top of the home page
- The About tab is `_tabs/about.md` with the default tab permalink (`/about/`
  under the `/blog` baseurl). Don't add an explicit `permalink: /blog/...` --
  Jekyll prefixes `baseurl` and you get `/blog/blog/about/`. The Minima
  leftovers (`about.markdown`, `index.markdown`) were removed for the same reason.
- **The blog is theme-vendored Chirpy**, not a plain gem install: the full theme
  source lives in `blog/` (`_sass/`, `_layouts`, `jekyll-theme-chirpy.gemspec`),
  tracked against an `upstream` remote for updates. `theme_mode: "dark"` forces
  dark mode.
- **"Control panel" retint:** the blog is restyled to match the landing page via
  an **append-only** block in `blog/assets/css/jekyll-theme-chirpy.scss` (Chirpy's
  reserved customization file) plus a font `<link>` in
  `blog/_includes/metadata-hook.html`. It only overrides dark CSS variables +
  fonts — no theme source edited, fully reversible (delete the block), and
  upstream-update-safe. Don't move these into `_sass/themes/_dark.scss`.

### Build / CI gotchas (learned the hard way)

- **CI needs Ruby ≥ 3.4.** `deploy-blog.yml` pins Ruby 3.4 on purpose: on 3.1 the
  bundled RubyGems was too old to recognize `sass-embedded`'s newer
  `x86_64-linux-gnu` platform tag, so Bundler fell back to the source gem and the
  native build failed at `bundle install`. Don't downgrade it.
- **Don't set `JEKYLL_ENV=production` in `deploy-blog.yml`.** In production
  Chirpy's stylesheet imports `main.bundle`, which only exists after the theme's
  npm build; CI has no Node step, so the build dies with "Can't find stylesheet
  to import". The blog therefore ships a development-mode build (uncompressed
  HTML, Bootstrap from the CDN, no PWA). Getting a production build means adding
  the npm build to the workflow first.
- **`blog/Gemfile.lock` is committed** (not gitignored) for reproducible builds —
  it pins the prebuilt `sass-embedded` linux gem so CI never tries to compile it.
  Regenerate it in the CI Ruby version if deps change (e.g. via `bundle lock`);
  the committed lock's `PLATFORMS` already covers linux gnu/musl + macOS.
- `deploy-blog.yml` triggers on `blog/**` **and** its own workflow path; the blog
  only deploys from `main`, and a failed build leaves the previous `gh-pages`
  output live (no downtime).

## Conventions

- Do NOT edit the `gh-pages` branch directly (managed by GitHub Actions)
- Tags are always lowercase
- Use descriptive commit messages (e.g., "New post: title here")
- PRs for new posts or big changes; direct push to `main` for typo fixes

## Publishing workflow

1. Write post in `blog/_posts/`
2. Commit and push to `main`
3. GitHub Actions builds and deploys automatically (takes about 1 minute)

For PRs:

```bash
git checkout -b post/title-slug
# write the post
git add .
git commit -m "New post: title here"
git push -u origin post/title-slug
gh pr create --title "New post: title here" --body "Draft for review"
```
